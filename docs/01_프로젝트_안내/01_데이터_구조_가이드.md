# 01. 데이터 구조 가이드

## 전체 구조

```text
원본 공간·기상 데이터
→ Edge 고정 데이터
→ Edge×시간 데이터
→ Heat Cost·군집
→ 추천경로·앱용 데이터
```

## 1) 원본 데이터: `data/raw/`

| 파일 | 쉬운 설명 | 핵심 사용정보 |
|---|---|---|
| `songpa_walkways.gpkg` | 송파구 보행도로 지도 | 도로 선, 도로 종류 |
| `songpa_boundary.gpkg` | 송파구 경계 | 분석범위 제한 |
| `buildings_seoul.zip` | 서울 건물 지도 | 건물 위치·외곽선 |
| `building_register.csv` | 건축물대장 | 건물 높이·층수 |
| `street_trees.csv` | 서울 가로수 | 위치·높이·수관폭 |
| `SWM_WKAR_AS.csv` | 서울 보도 포장재 | 포장재 위치·코드 |
| `SWM_BASIC_CODE.csv` | 포장재 코드표 | 코드 설명 |
| `asos_hourly.csv` | 시간별 서울 기상 | 기온·습도·풍속·강수·일사량 |
| `jamsil_iot_observations.xlsx` | 잠실 환경별 지면온도 | 방향성 검증 |
| `measured_surface_temperature.csv` | Edge 실측온도 입력 양식 | 현재 헤더만 존재 |

## 2) Edge 고정 데이터: `data/processed/edges_static.gpkg`

한 행이 도로 한 구간입니다. 총 3,797개입니다.

- `edge_id`: PawSafe 도로 ID
- `geometry`: 지도 위 도로 선
- `length_m`: 도로 길이
- `surface_code`: 포장재 코드
- `surface_absorptivity`: 포장재 흡수율

## 3) Edge×시간 데이터

파일은 같은 내용을 두 형식으로 저장합니다.

- `edge_time_features.csv`: Excel 등에서 확인하기 쉬움
- `edge_time_features.parquet`: 코드에서 빠르게 읽기 좋음

한 행은 **특정 Edge의 특정 시간 상태**입니다.

```text
3,797개 Edge × 24시간 = 91,128행
```

주요 열은 다음과 같습니다.

| 구분 | 주요 열 |
|---|---|
| 식별 | `edge_id`, `timestamp` |
| 기상 | 기온, 습도, 풍속, 강수, 일사량 |
| 그림자 | 그림자율, 태양고도·방위각 |
| 누적노출 | 최근 직사광선 시간, 누적 유효 일사량 |
| 포장재 | 포장재 코드, 흡수율 |
| 열환경 | 열저장 Proxy, 군집, Heat Cost |

지도 위치는 `edges_static.gpkg`, 시간별 값은 `edge_time_features.*`에 저장되며 `edge_id`로 연결합니다.

## 4) 결과 데이터: `outputs/`

- 열지도: Edge별 Heat Cost
- 군집결과: K-means/GMM 평가와 군집 특성
- 경로결과: Fast·Cool 거리와 Heat Cost
- IoT 검증: 고열·저열 예상 환경의 온도 차이
- 앱용 결과: 화면에서 바로 읽을 GeoJSON
